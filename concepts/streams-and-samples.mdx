The MTConnect Agent exposes all device data over a REST API. This page covers the full client workflow: probing for device metadata, reading current values, streaming observations from the circular buffer, querying with XPath, and retrieving assets.

## The Four Core Requests

| Endpoint | What it returns |
|----------|----------------|
| `GET /probe` | Device structure and all data item definitions |
| `GET /current` | Latest snapshot of every data item, with timestamps |
| `GET /sample` | Sequence of observations from the Agent's circular buffer |
| `GET /assets` | Assets associated with devices (cutting tools, fixtures, pallets, etc.) |

## Step 1 — Probe for Metadata

Always start with `/probe`. It describes every device, component, and data item the Agent knows about. Use it to discover what data is available before querying.

```bash
curl http://localhost:5000/probe
```

```xml
<MTConnectDevices>
  <Header instanceId="1" nextSequence="3274" ... />
  <Devices>
    <Device id="dev1" name="Mazak" uuid="MAZAK001">
      <Components>
        <Controller id="ctrl1">
          <DataItems>
            <DataItem id="exec1" type="EXECUTION" category="EVENT"/>
            <DataItem id="mode1" type="CONTROLLER_MODE" category="EVENT"/>
          </DataItems>
        </Controller>
      </Components>
    </Device>
  </Devices>
</MTConnectDevices>
```

<Warning>
  The `instanceId` in the header can change whenever the Agent reboots. Always check and track `instanceId` — if it changes, your sequence numbers are no longer valid and you should re-sync from `/current`.
</Warning>

## Step 2 — Read Current Values and Get nextSequence

Call `/current` to get the latest value of every data item. Critically, the response header includes `nextSequence` — the sequence number to use when you start polling `/sample` so you don't miss any observations.

```bash
curl http://localhost:5000/current
```

```xml
<MTConnectStreams>
  <Header nextSequence="3274" firstSequence="1274" lastSequence="3273" ... />
  <Streams>
    <DeviceStream name="Mazak">
      <ComponentStream component="Controller">
        <Events>
          <Execution dataItemId="exec1" timestamp="2024-01-15T10:23:45.000Z">ACTIVE</Execution>
          <ControllerMode dataItemId="mode1" timestamp="2024-01-15T10:23:45.001Z">AUTOMATIC</ControllerMode>
        </Events>
      </ComponentStream>
    </DeviceStream>
  </Streams>
</MTConnectStreams>
```

## Step 3 — Sample from nextSequence Forward

Once you have `nextSequence` from `/current`, pass it as the `from=` parameter to `/sample`. The Agent will return only observations that occurred after that point, so you never receive duplicates or miss a value.

There are two approaches depending on your use case:

**Polling** — your client requests new data on a fixed interval. Simple and reliable; works well when you don't need sub-second latency.

**Server-side streaming (push)** — add an `interval=` parameter and the Agent holds the connection open, pushing new data as it arrives. No repeated HTTP overhead; better for real-time dashboards.

### Polling example

```python
import requests
import time
import urllib3
from datetime import datetime
import xml.etree.ElementTree as ET

# Disable SSL warnings for self-signed agent certificates
urllib3.disable_warnings(urllib3.exceptions.InsecureRequestWarning)

BASE = "http://mtconnect.mazakcorp.com:5611"
NS = {"m": "urn:mtconnect.org:MTConnectStreams:2.0"}

def get_next_sequence():
    """Seed the starting sequence from /current so we don't replay old data."""
    r = requests.get(f"{BASE}/current", verify=False, timeout=10)
    r.raise_for_status()
    root = ET.fromstring(r.text)
    header = root.find(".//m:Header", NS)
    return int(header.attrib["nextSequence"])

def poll():
    last_seq = get_next_sequence()
    print(f"Starting poll from sequence {last_seq}")
    print("-" * 50)

    while True:
        try:
            r = requests.get(
                f"{BASE}/sample?from={last_seq}&count=100",
                verify=False,
                timeout=10
            )
            r.raise_for_status()

            root = ET.fromstring(r.text)
            header = root.find(".//m:Header", NS)
            last_seq = int(header.attrib["nextSequence"])

            timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
            print(f"\n[{timestamp}] nextSequence now: {last_seq}")
            print(r.text)

            time.sleep(5)

        except KeyboardInterrupt:
            print("\nStopped polling")
            break
        except Exception as e:
            print(f"Error: {e}")
            time.sleep(5)

if __name__ == "__main__":
    poll()
```

### Server-side streaming (push) example

Add `interval=` (milliseconds) to have the Agent push data continuously over a single open connection:

```bash
# Push new observations every 1 second, starting from sequence 3274
GET /sample?from=3274&interval=1000

# Push only part count changes, every 2 seconds
GET /sample?from=3274&interval=2000&path=//DataItem[@type="PART_COUNT"]
```

<Tip>
  Use `interval=0` to have the Agent deliver data at the highest possible rate — useful for high-frequency data capture.
</Tip>

## Querying the Agent with XPath

The Agent supports **XPath** as a query language. Append a `path=` parameter to any request to filter the response down to exactly the data items you need. XPath queries that don't match anything return an error.

### /current XPath examples

```bash
# Get availability of all devices
GET /current?path=//DataItem[@type="AVAILABILITY"]

# Get availability for a specific data item id
GET /current?path=//DataItems/DataItem[@id="avail"]

# Get all condition statuses
GET /current?path=//DataItems/DataItem[@category="CONDITION"]

# Get all data items in the Controller component
GET /current?path=//Controller/*

# Get all linear axis data items
GET /current?path=//Axes/Components/Linear/DataItems

# Get data items for a specific linear axis
GET /current?path=//Axes/Components/Linear[@id="x1"]

# Get the Execution data item
GET /current?path=//Controller/Components/Path/DataItems/DataItem[@type="EXECUTION"]

# Get Execution AND ControllerMode in one request
GET /current?path=//Controller/Components/Path/DataItems/DataItem[@type="EXECUTION" or @type="CONTROLLER_MODE"]

# Get actual rotary velocity for all spindles
GET /current?path=//Axes/Components/Rotary/DataItems/DataItem[@type="ROTARY_VELOCITY" and @subType="ACTUAL"]

# Combine multiple paths with | (pipe)
GET /current?path=//DataItems/DataItem[@category="CONDITION"]|//Controller/*|//DataItem[@type="AVAILABILITY"]
```

### /sample XPath examples

```bash
# Get the last 4095 part count observations
GET /sample?path=//DataItem[@type="PART_COUNT"]&count=4095

# Get part count observations from a specific sequence number
GET /sample?path=//DataItem[@type="PART_COUNT"]&from=13&count=4095

# Stream asset change events with a 2-second interval
GET /sample?from=172&interval=2000&path=//DataItems/DataItem[@type="ASSET_CHANGED" or @type="ASSET_REMOVED"]
```

## Assets

Assets are objects associated with a manufacturing process but not permanently attached to a device — cutting tools, fixtures, pallets, and raw materials are common examples. They are retrieved via `/assets` or `/asset/{id}`.

### Supported asset types

| Asset type | Description |
|------------|-------------|
| `CuttingTool` | Tool geometry, life management, process parameters |
| `CuttingToolArchetype` | Template definition for a class of cutting tools |
| `Fixture` | Workholding fixture definitions (v2.5+) |
| `Pallet` | Pallet definitions (v2.5+) |
| `RawMaterial` | Raw material stock associated with a process |
| `Part` | Part identity, revision, and drawing references (v2.7+) |
| `PartArchetype` | Template definition for a class of parts (v2.7+) |
| `Task` | Manufacturing task with lifecycle state tracking (v2.7+) |
| `Process` | Manufacturing process definition and steps (v2.7+) |

### Asset query examples

```bash
# Get all assets
GET /assets

# Get a specific asset by ID
GET /asset/EDP1234

# Get only cutting tool assets
GET /assets?path=//Assets/DataItems/DataItem[@type="CuttingTool"]

# Get the AssetChanged event (tells you when an asset was updated)
GET /current?path=//Devices/Device/DataItems/DataItem[@type="ASSET_CHANGED"]

# Watch for asset changes and removals
GET /current?path=//DataItems/DataItem[@type="ASSET_CHANGED" or @type="ASSET_REMOVED"]
```

### Example cutting tool asset response

```xml
<Assets>
  <CuttingTool assetId="EDP1234" serialNumber="1234" toolId="EDP">
    <CuttingToolLifeCycle>
      <ToolLife countDirection="UP" initial="0" limit="150" type="MINUTES">
        <value>47</value>
      </ToolLife>
      <Measurements>
        <FunctionalLength maximum="63.5" minimum="60.5" nominal="62.0" units="MILLIMETER">62.1</FunctionalLength>
        <CuttingDiameterMax nominal="25.4" units="MILLIMETER">25.4</CuttingDiameterMax>
      </Measurements>
    </CuttingToolLifeCycle>
  </CuttingTool>
</Assets>
```
